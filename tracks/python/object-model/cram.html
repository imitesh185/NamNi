Object Model 1.1–1.3 · CRAM

The chant

Five lines. Everything below is a consequence of them.

  1. A name is a key, not a box.
  2. A container holds references, not objects.
  3. = changes a slot. A method changes the object.
  4. Shared + mutated = visible. Everything else is private.
  5. Nothing is copied unless you ask — and then only one level.
01Object
Definition

Everything is an object: a thing with an identity, a type and a value.

What it holds
  • identity — its address, for its whole life
  • type — a pointer to one shared type object
  • value — whatever the type says it is
Thumb rules
  • An object's address never changes.
  • "The id changed" always means a different object is there.
a = [1,2]
id(a); a.append(3); id(a)  # same  → mutation
a = a + [4];       id(a)  # new   → rebinding
02Identity — is vs ==
Definition

is asks “same object?”. == asks “same value?” and runs the type's __eq__.

What it holds
  • id(x) holds an address [CPython]
  • unique only among objects alive at the same time
  • a dead object's address is reused immediately
Thumb rules
  • is only for None, True, False, sentinels.
  • Never store or compare ids across time.
  • x is 5 works by accident — small ints are cached.
03Name & binding
Definition

A name is a key in a namespace mapping to an object reference. A namespace is that mapping.

What it holds
  • the namespace holds name → reference pairs
  • the object holds the data — never the name
  • binds: = def class import for as := params
Thumb rules
  • b = a → two keys, one object.
  • del x removes the binding, not the object.
  • The object dies only when its last reference goes.
04LEGB & shadowing
Definition

Name lookup searches Local → Enclosing → Global → Builtins. First hit wins; miss all four → NameError.

What it holds
  • each level is an ordinary mapping — builtins included
  • globals() is live; locals() is a snapshot
  • function locals are array slots, not a dict [CPython]
Thumb rules & traps
  • Builtins are shadowable → 'list' object is not callable. Fix: del list.
  • A class body is not an enclosing scope — use self.x / C.x.
  • for leaks its variable; a comprehension does not.
  • except … as e deletes e at block exit.
05Container = array of references
Definition

A list does not contain objects. It contains references to objects — a contiguous array of pointers.

What it holds
  • a contiguous array of pointers — the objects live elsewhere
  • same for dict values, tuple slots and obj.__dict__
  • * and slicing copy the pointers, never the objects
Thumb rules
  • Never [[...]] * n. Use a comprehension.
  • [0]*3 shares too — you just can't observe it.
r = [[]] * 3
r[0].append('x')   # [['x'],['x'],['x']]
06Aliasing
Definition

Two or more references to one object — regardless of where those references live.

What it holds
  • n references, 1 object. Nothing was duplicated.
  • even a.append(a) — a container can alias itself
Thumb rules
  • Test sharing with is, never ==.
  • Probe a container: [hex(id(v)) for v in c]
07Rebind vs Mutate — THE ONE
Definition

Rebinding (x = …, x[i] = …) changes which object a slot points to. Mutation (x.append(…)) changes the object itself.

What it holds
  • rebinding touches the slot — the object is untouched
  • mutation touches the object — every slot pointing at it sees the change
Thumb rules
  • Ask only two things: rebind or mutate? then is it shared?
  • Only mutation of a shared object is visible elsewhere.
r = [[]] * 3
r[0] = 9            # [9, [], []]
r[0].append('x')   # [['x'],['x'],['x']]
08Copy depths
Definition

Three depths only: alias (nothing new), shallow (new outer, shared inner), deep (new everything mutable).

What it holds
  • the three shallow spellings are identical in effect
  • matching element ids are proof of shallowness, not of aliasing
Thumb rules
  • Two booleans identify the depth, always:
b is a, b[0] is a[0]
# T,T alias   F,T shallow   F,F deep
09deepcopy internals
Definition

Deep copy rebuilds everything that could be mutated, and returns immutables unchanged.

What it holds
  • a memo dict mapping id(obj) → copy
  • a type dispatch table; immutables map to “return x”
Thumb rules
  • Copy only what could be mutated — sharing an unmutatable object is unobservable.
  • True at any size, not just cached small ints.
n = 10**50
copy.deepcopy(n) is n   # True
10Arguments & mutable defaults
Definition

Parameters are bindings in the function's new namespace. Not by-value, not by-reference — the same rule as everywhere else.

What it holds
  • the call frame holds a new binding to the same object
  • f.__defaults__ holds default objects, built once at def time
Thumb rules
  • Never a mutable default — it is shared by every call.
  • Never say “by value / by reference”.
def f(x, bucket=None):
    bucket = [] if bucket is None else bucket
11The += paradox
Definition

x[i] += v is three operations: load the slot, run the in-place op, store the result back.

What it holds
  • list has __iadd__; tuple has none
  • in-place ops return self — that is why they are visible to aliases
Thumb rules
  • a += [3] mutates → every alias sees it.
  • a = a + [3] rebinds → no alias sees it.
  • x[i] += v is not atomic — it can mutate and raise.

Kill list

Six habits. Each is a bug you would otherwise ship.

NEVER [[...]] * nUse a comprehension. Always.
NEVER a mutable default=None, then build inside.
NEVER shadow a builtinlist dict str id type len.
NEVER trust "a copy"Check b[0] is a[0].
NEVER cache id()Addresses are recycled on death.
NEVER say by-value / by-referenceSay: rebinding vs mutation.

The six answers

If any of these reads as new rather than familiar, the card above it is the one to re-read.

  1. [[]]*3 vs [0]*3 — both build three slots pointing at one object. rows[0].append("x") mutates the shared object, so all three show it. nums[0] = 9 rebinds one slot, so only that slot changes. Immutability never enters the explanation.
  2. Three copy depths, two booleans — alias (same outer, same inner), shallow (new outer, same inner), deep (new outer, new inner). The two tests are c is orig and c[0] is orig[0]; the second is the one that matters.
  3. Why deepcopy won't copy an int — copying only means anything for an object that can be mutated. An immutable object can be shared with no risk, so deepcopy returns the original rather than wasting an allocation.
  4. The += paradox — step 2 commits (__iadd__ mutates the inner list in place); step 3 fails (assigning the result back into the tuple slot). One statement, an exception and a completed mutation.
  5. Why a mutable default accumulates — the default object is built once, when def executes, and stored on the function object. You can see it in fn.__defaults__.
  6. The three questions, in order — which slot → rebind or mutate → is it shared? that is the whole stage
